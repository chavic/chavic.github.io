~/work/bdk-dart/challengeBDK already had solid Rust + FFI, but no official Dart story. Wallet teams were hand-rolling bindings or using third-party packages. The brief was to create a maintainable, language binding aligned with other BDK ecosystems so Flutter teams can ship descriptor-based wallets without touching Rust.
~/work/bdk-dart/approach
How I shipped language bindingsTreated bindings as product: aligning with upstream types, keeping the FFI surface predictable, baking scripts/CI to regenerate and test, and shipping examples so teams can adopt quickly. Here are a few work samples
Binding integration & repo architectureMigrated the Dart package into the BDK org, structured around bdk-ffi (Rust sources), generated lib/bdk.dart, examples, tests, and a bdk_demo Flutter app; wired the root crate to the bdk-ffi submodule.
Local codegen & toolingAdded a uniffi-bindgen wrapper and scripts to rebuild libbdkffi.* and lib/bdk.dart in one step; removed hand-rolled Rust scaffolding in favor of the submodule + generator pipeline.
CI & quality gatesIntroduced GitHub Actions to build, generate bindings, and run tests; tightened analysis by making dart analyze fatal; refreshed labels and Dart-only args for debuggable pipelines.
Developer flows & examplesUpdated the core example into a network/wallet bootstrap demo and added a minimal bdk_demo Flutter app so teams can point at Android/iOS once bindings are generated.
~/work/bdk-dart/impact
Enables production mobile wallets to leverage Bitcoin Dev Kit from Flutter with safe Rust FFI.
Automated build scripts ship signed Android/iOS artifacts in CI.
Reduced wallet crashes/regressions with integration tests against BDK node fixtures.
bdk-dart is now the official Dart binding in the BDK ecosystem, aligned with bdk-ffi and maintained alongside other language frontends.
Teams can build Flutter wallets on descriptor-based BDK primitives with a generated, null-safe Dart API instead of bespoke FFI glue.
CI, scripts, and layout let contributors regenerate bindings and run tests with a single script, keeping the project sustainable as BDK evolves.
